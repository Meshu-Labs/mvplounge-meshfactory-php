## Tier Definitions

| Tier | Meaning | Typical next step |
|---|---|---|
| Unbound | Enum case exists but no concrete class is bound to it. | Create the class (see [backlog](../behavior/BV-element-factory-implementation-backlog.md)). |
| Stub | Class only binds the element; no element-specific attributes or behavior. Renders `<tag>` plus global attributes and content. | Model spec attributes in the nearest family abstract. |
| Family | Inherits element-specific attributes from a family abstract; no leaf behavior. | Verify attribute completeness and rendered output. |
| Behavioral | Leaf declares its own public behavior (children, composition, fluent helpers). | Harden behavior, escaping, and string/array parity. |

## Legend

- Tests: uppercase `G` Generic, `F` Factory, `P` Params means a per-class sandbox script exists. Lowercase `g`, `f`, `p` means the class is only covered by a domain suite (Field, Form, Table) in that flavor. `-` means no sandbox coverage.
- Spec attributes: non-global attributes the HTML Standard defines for the element that the class does not yet allow. Curated list lives in the generator. `input` is type-dependent and excluded from the automatic diff.
- Allowed, not in spec: attributes the class allows (and therefore may render) that the HTML Standard does not define for the element. The MeshFactory-specific `access` pseudo attribute is ignored.
- TS atom: closest Mesh UI Foundation Part/Module (`C:\_src\app-mesh-ui\src\library\Foundation`). TS atoms are composite wrappers, not 1:1 tags; see [TypeScript alignment](AX-element-factory-typescript-alignment.md).
- EELC: concrete class is imported directly by APP-EELC facades or designers.

## Notes

- `fieldset` is implemented by `Element/Form/Fieldset`, a concrete subclass of the abstract `FactoryElementFieldsetAbstract`. It stores an optional `FieldsetLabel`, and is used by fields, `FormButton` and form sections.
- `tbody` and `tfoot` are bound by `TableRowBody` and `TableFooter`; `table` is bound by `TableBody` and `DataTableBody` (names do not match their tags).
- Classes in `Element/Form` that use the `MvpLounge\MeshFactory\Element\Field` namespace (`InputText`, `InputEmailer`, `InputPassword`, `InputHidden`, `InputRadio`, `FormButton`, `SelectOption`, `SelectOptions`) only autoload through the Composer classmap, not PSR-4.
